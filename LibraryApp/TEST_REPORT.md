# Отчет о тестировании приложения LibraryApp

## 1. Объект тестирования

Консольное приложение LibraryApp, реализующее простую бизнес-логику учета книг в библиотеке (добавление, выдача, возврат).

## 2. Методика тестирования

В ходе работы использовались следующие методы:
- Ручное тестирование граничных случаев.
- Отладка с использованием точек останова и пошагового выполнения (F10/F11).
- Статический анализ кода с помощью встроенных анализаторов .NET.

## 3. Найденные дефекты

| ID | Описание | Шаги воспроизведения | Ожидаемый результат | Фактический результат | Статус |
|----|----------|----------------------|---------------------|-----------------------|--------|
| 1 | Выдача несуществующей книги | Вызвать `BorrowBook(3)` | Сообщение об ошибке | Падение с `NullReferenceException` | Исправлен |
| 2 | Повторная выдача книги | Вызвать `BorrowBook(1)` дважды | Отказ в выдаче | Книга выдается повторно | Исправлен |
| 3 | Возврат невыданной книги | Вызвать `ReturnBook(2)` для книги, которая не выдавалась | Сообщение об ошибке | Книга возвращается | Исправлен |

## 4. Результаты инспекции кода

По результатам статического анализа были внесены следующие изменения:
- Классы `Book` и `Library` сделаны внутренними (`internal`).
- Свойства `Title` и `Author` объявлены как nullable (`string?`).
- Возвращаемый тип метода `FindBook` изменен на `Book?`.
- Удален искусственный блок `try-catch` в `Program.cs`, использовавшийся только для отладки.
- Добавлены поясняющие комментарии к сложным участкам кода.

Предупреждение CA1303 (использование строковых литералов вместо ресурсов) оставлено без изменений, так как не является критичным для консольного приложения.

## 5. Итоги
Все найденные дефекты исправлены. После повторного запуска программа корректно обрабатывает граничные случаи, не падает и выводит понятные сообщения об ошибках.
